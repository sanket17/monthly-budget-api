<objective>
Prove the generation algorithm Plan 06-01 built is correct under the hard cases — backfill depth, the creation-month boundary, concurrent double-generation, manual-deletion survival, and one-entry-fails-the-rest — and close the one remaining cross-app gap: blocking a category's soft-delete while an active recurring entry still references it (D-15).

Purpose: these are exactly the decisions (D-07/08/09/10/11/14/19) RESEARCH.md identified as the phase's real technical risk — five interacting rules folded into one walk-forward loop. This plan is where that loop earns its correctness proof, plus the one piece of "other app" cross-cutting work (D-15) that's easy to miss since it changes existing, already-working code in `budget`, a different app than where the new feature lives.
Output: an exhaustively tested `recurring/services.py` generation path and a `budget/views.py::CategoryViewSet.perform_destroy` that rejects deletion while a live recurring entry depends on the category.
</objective>
