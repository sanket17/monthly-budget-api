<assumption_delta_decision>
Transaction gains a nullable `recurring_entry` FK (D-20), introducing a plural "origin of a transaction" where there was previously exactly one (manual entry). Per CONTEXT.md D-20/D-21 this is an **add-alongside** generalization, not a promotion: Transaction keeps its existing identity and every current call site (TXNS-01..07 CRUD, `get_bank_balance`, `get_emergency_fund_balance`, credit-card/dashboard aggregation) continues to work unchanged for manually-created transactions (`recurring_entry=null`). The FK is an optional, read-only origin marker exposed in the API — never a replacement for Transaction's role as the single source of truth for a user's money movement. No existing Transaction-consuming code needs to branch on `recurring_entry`: a recurring-generated expense must affect the bank balance exactly like a manually-entered one, so every balance/aggregation query keeps summing every Transaction row regardless of origin.
</assumption_delta_decision>
